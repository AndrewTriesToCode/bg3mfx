# October 10 main-menu validation

**Historical result:** the Temporal jitter workaround below passed abort-on-fault
validation for all four qualities and returning Options → main menu. The user
requested its removal on October 11; these passes do not apply to the current
runtime, which uses BG3's original jitter table.

Tested BG3 4.1.1.7631656 on Apple M5 Pro, macOS 27.0, windowed 1280×800,
Metal HUD on, direct executable launch with `-NoLauncher 1`. No gameplay or
saves were loaded. Original bundle/executable bytes were preserved.

## Fixed

Temporal had incorrectly applied the bounded FSR color decoder to pre-TAA
linear HDR. Captured color values reached 59; inverse compression could
therefore overflow RGBA16Float. Temporal now copies HDR at its input and output.
This does not enable HDR display output. Spatial's older bounded-color decoder
was replaced on October 11 with the linear-HDR path documented in
`../2026-10-11-spatial.md`.

Closing Options reapplied custom enum values through the native ApplyComboBox,
which disabled upscaling. The guarded virtual apply hook now temporarily sends
native value 1 for custom 2/3 and restores the visible selection. Both MetalFX
modes remained active on the main menu after Back.

## Historical Temporal jitter workaround — later October 10 run

Isolation found that repeating original capture frame 2 also fails: changing
scene data/history is unnecessary. Its jitter is (-0.4375, -0.388889). Holding
jitter fixed at frame 0 while changing each/all input planes passes. Negating
jitter, aligned input allocations, auto exposure, dynamic-content configuration,
and asynchronous scaler initialization did not resolve the original fault.
Adding 0.5 to jitter passed but violates Apple's documented centered convention
and was **not** adopted. Merely halving the values reported to MetalFX would
misdescribe the rendered image and was **not** adopted.

The October 10 guarded native menu runtime adapted BG3's shared eight-sample
Halton table at 0x107b21738 only while Temporal is selected. Each stored sample
becomes `0.5 + (original - 0.5) * 0.5`. Both GetJitteredProjectionMatrix and
UpdateConstantBuffersData read this same table, so projection, shader jitter,
and motion compensation remain consistent. Off/FSR/Spatial restore the exact
original table. This is a half-amplitude sampling workaround for the observed
MetalFX kernel fault, with a potential reconstruction-quality tradeoff; it does
not fix Apple's private kernel or bypass its validation. Native table bytes and
the ARM64 game UUID are checked before modification. Bundle bytes stay original.

`build/game-temporal-jitter-fixed.{log,jsonl}` (PID 95908) ran Metal API and shader
validation with abort-on-fault enabled. The only excluded pipeline was the

pipeline was excluded.** No invalid Metal usage was reported across more than

### Gameplay postprocess chain repair

The multiple-view repair alone did not resolve the live failure. A bounded
diagnostic encoder history (`BG3MFX_TRACE_TEMPORAL_CHAIN=1`, diagnostic runtime
only) in `build/game-city-chain.jsonl` identified the actual intervening passes:
PPTAA → bloom/color grading → outline combine → fragment FSR_Tonemap. They
alternate between two HDR targets; FSR_Tonemap writes a separate bounded-color
texture. Its output is therefore not necessarily the original PPTAA output.
Lower City loaded at Balanced and survived initial camera moves, but after
switching to Quality another pan/rotation hit the mismatched texture and exited
78. No native FSR fallback ran.

The hook now forwards the exact scene association through those identified
color passes, invalidates an association when its target is overwritten, and
supplies the last linear HDR input before FSR_Tonemap to MetalFX. Depth, motion,
and camera remain associated with that scene. Unknown transformations fail
closed. The GPU regression now models separate FSR_Tonemap output, a secondary
view, and a bloom pass that changes HDR pixels. Both quiet and diagnostic
runtimes pass API and abort-on-fault shader validation with expected HDR pixels
and zero native FSR dispatches. Eight Python tests pass.

## October 11 current status

The user decided to remove the reduced-jitter workaround. `NativeMenu.mm` no
longer checks or modifies BG3's shared Halton table; the launch command no
longer has a `BG3MFX_DISABLE_JITTER_WORKAROUND` switch. Temporal now always
uses the game's original jitter pattern. The earlier validation results in the
workaround section are historical and do not apply to this runtime. The original
negative outer samples previously reproduced a MetalFX BBR shader-validation
fault, so Temporal's clean validation status is unresolved until it is retested
with the current build. After removal, both runtime libraries rebuilt, all
eight Python tests passed, and the default three-frame Temporal synthetic GPU
smoke passed. The full native-jitter sequence was not rerun because its known
validation fault remains unresolved; no BG3 process was launched.
